# Audio API Completion Plan

1. Capture the latest OpenAI spec for `/v1/audio/transcriptions` and `/v1/audio/translations`, documenting request fields (`response_format`, `timestamp_granularities`, `user`, `language`, `prompt`, etc.), valid response bodies (text/json/verbose_json/srt/vtt), and usage semantics in `docs/api/audio.md`, linking from `ROADMAP.md`.
2. Extend `backend/internal/models/audio.go` and related types so transcription requests include response format, timestamp granularity preferences, user metadata, and input descriptors; ensure responses can carry raw payload bytes, parsed text, verbose JSON segments, and usage stats.
3. Update `backend/internal/httpserver/public/audio_routes.go` to parse all spec parameters (support both `file` and `audio`, enforce max upload size/mime types, handle `response_format`, `timestamp_granularities[]`, `language`, `prompt`, `user`, `temperature`) and emit correctly formatted responses for each format.
4. Expand provider interfaces/capabilities (`backend/internal/providers/interfaces.go` plus route metadata) so adapters advertise supported audio formats/granularities, enabling the router to short-circuit unsupported requests.
5. Enhance the OpenAI, Azure OpenAI, and other openai-compatible adapters to send the new fields (response format, timestamp granularity) and return full responses—including usage for translations—and capture raw payloads for non-JSON formats.
6. Introduce handler + adapter tests covering multipart parsing, invalid inputs, each response format, timestamp granularity fallbacks, and translation flows using deterministic fixtures (`backend/internal/httpserver/public/audio_routes_test.go`, adapter-specific tests).
7. Refresh documentation (`README.md`, `docs/runtime/config.md`, audio spec doc, ROADMAP progress log) detailing the new audio capabilities, env/config knobs (max upload MB, supported formats), and any limitations (e.g., streaming transcriptions TBD).
8. (Optional follow-up) Decide on SSE streaming support for transcriptions; either implement now by extending models + handlers + adapters, or log a dedicated backlog item outlining acceptance criteria and dependency on upstream providers.
